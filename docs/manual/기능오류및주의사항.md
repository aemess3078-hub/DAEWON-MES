# 기능 오류 및 매뉴얼 작성 시 주의사항

기준: 이 워크트리 HEAD `7d9b880`(origin/main과 동일, 확인 시점 기준). **코드 수정·데이터 변경 없이** 소스 읽기와 화면 관찰만 수행했다. 해결 여부는 이 커밋 기준이며 다른 브랜치/원본 작업 폴더의 수정 여부는 확인하지 않았다 [미확인].

## ISSUE-01 자재출고와 생산실적 등록 규칙 충돌
- **조건**: BOM 단위 소요량(손실률 포함)으로 `producible = floor(출고량 ÷ 단위소요)`를 계산할 때 부동소수점 오차가 생기는 수량·손실률 조합(예: 77.25 ÷ 2.575 → 29.999999).
- **현상**: (a) 필요량만큼만 출고하면 마지막 1개가 "출고된 자재 기준으로 최대 29.999999 EA까지…"로 거부되어 전량 실적 등록 불가. (b) 필요량을 조금 넘겨 출고하면 출고 액션이 BOM 필요량 초과로 거부. 이전 작업에서 데이터 생성 중 실제로 발생.
- **영향 메뉴**: 자재출고현황(04-03), POP 작업 화면(07-02, 실적 등록), 작업지시.
- **소스**: `src/lib/bom-material-sufficiency.ts` `floorQty`(77~80행: `Math.floor((value+Number.EPSILON)*1e6)/1e6`), 호출 143행, 한도 검사 `assertProductionQuantityWithinMaterialLimit`(190~202행), 출고 한도는 자재출고 액션 [SRC].
- **기존 테스트**: `tests/e2e/tc-n17-material-issue.e2e.ts`의 `[N17-10]`이 출고분 기준 floor 규칙을 검증하나 부동소수점 케이스는 다루지 않는다 [SRC]. 테스트 실행 결과 기록은 확인하지 못함 [미확인].
- **해결 여부**: 이 커밋에서는 **미해결**(`floorQty`는 최초 커밋 이후 변경 없음).
- **매뉴얼 주의**: 시나리오 수량은 이 오차가 없는 값(반제품 32, CAP 원판 110 등)을 유지한다. 수량 예시를 임의로 바꾸지 말 것.

## ISSUE-02 최종검사 화면의 양품수량 부풀림
- **조건**: 공정이 여러 개인 작업지시(S01 WO-2026-003은 7공정).
- **현상**: 최종검사 화면 "양품 수량"이 실제 20개가 아니라 모든 공정의 양품 합(20×7=140)으로 표시 [이전 작업 UI 확인, 이번 작업에서는 재조회 안 함].
- **영향 메뉴**: 최종검사(09-03, 메뉴 없음/직접 URL). 완제품입고(06-05) "계획/입고 기준 20/20"은 정상. DB 수량은 정확.
- **소스**: `src/lib/actions/finished-goods.actions.ts` `calculateReceiptQuantity` — `totalGoodQty`가 `operations` 전체의 `goodQty`를 합산(약 99~106행). 화면은 `final-inspection-data-table.tsx`의 `totalGoodQty` 열(67~71행) [SRC 확인].
- **기존 테스트**: 해당 열에 대한 테스트는 찾지 못함 [미확인].
- **해결 여부**: 미해결.
- **매뉴얼 주의**: 최종검사 화면의 양품 수량 숫자를 설명·캡처 값으로 쓰지 말 것(완제품입고 화면 수량 사용).

## ISSUE-03 (이번 조사에서 새로 발견) POP 작업 화면 잔여수량·경고 오표시
- **조건**: 설비배정이 있는 공정에서 일부 양품만 등록한 상태(S02 WO-2026-004 2공정: 계획 50, 완료 20, 불량 0).
- **현상 [UI]**: 카드 경로(`?assignmentId=`)로 열면 "배정수량 50 / 완료수량 20 / **잔여수량 10**"과 함께 "⚠ **전공정 불량으로** 투입 가능 수량이 감소했습니다. 잔여 투입 가능: 10개"가 표시된다. 실제 불량은 0이고 잔여는 30이어야 한다.
- **원인 추정 [SRC]**: `pop.actions.ts` `getOperationDetail`에서 `availableWipQty = 루트 WIP − 지금까지 양품`(=30)을 이미 계산하는데, `production-client.tsx`에서 `wipLimitedRemaining = availableWipQty − completedQty`로 완료수량을 한 번 더 뺀다(=10) → 이중 차감. 서버 등록 검증(`availableInputScaled = 루트 qty − goodSoFar`)은 30까지 허용하므로 **표시만 틀리고 등록은 가능**해 보이나 실행해 확인하지 않았다 [미확인].
- **영향 메뉴**: POP 작업 화면(07-02). 단계별 부분 실적 입력이 있는 모든 공정.
- **기존 테스트/해결**: 관련 테스트 없음 확인, 해결 여부 미확인(미해결로 추정). 이전 작업에서는 발견되지 않았다.
- **매뉴얼 주의**: S02 POP 진행중 화면 캡처(`07-02_POP_작업화면_카드경로_WO-2026-004_2공정.png`)에는 이 오표시가 포함된다. 캡처 사용 시 해당 문구를 가리거나, 수정 후 재캡처할 것. `07-02_POP_작업화면_진행중_S02.png`(assignmentId 없는 URL)에도 잔여 10이 표시된다.
