# 화면별 기능 조사

근거 표기: **[UI]** 실제 Edge 화면에서 확인 · **[SRC]** 소스코드만 확인 · **[미확인]** 확인하지 못함. 오너(OWNER) 계정으로 확인했으며 역할별 버튼 표시는 확인하지 못했다([미확인], `minRole`만 소스 확인). 필수 입력은 화면에 `*`로 표시된 항목만 기록했다(저장 검증은 저장을 눌러야 알 수 있어 [미확인]).


## 01 시스템 시작

### 01-01 로그인 / 모드 선택 (`/login`)
- **[UI]** 모드 선택 화면에 **시스템모드**(관리자·생산관리자용 PC)와 **작업자모드**(현장 태블릿·키오스크 터치용) 두 카드가 있다.
- 시스템모드: 아이디·비밀번호(둘 다 필수*), [로그인], "비밀번호를 잊으셨나요?", [← 모드 선택으로]. 로그인 후 `/app`으로 이동 [SRC].
- 작업자모드: **4자리 POP PIN** 숫자패드(0~9, C, 확인). PIN 형식 오류·미등록 시 "등록되지 않았거나 사용할 수 없는 작업자 PIN입니다…" [SRC]. 성공 시 `/pop/work-select` [SRC]. **PIN 입력은 로그인 기록(LoginHistory)을 남기므로 이번 조사에서 입력하지 않음 → PIN 로그인 동작은 [미확인].**
- 캡처: `01_시스템시작/01-01_*`, `07_POP/07-00_POP_작업자PIN로그인.png`
- **관리자 비밀번호 로그인은 [미확인]**: 비밀번호를 보유하지 않아 관리자 세션 쿠키(JWT)를 주입해 로그인 상태로 조사했다. 로그인 폼 제출 경로는 확인하지 못함.

### 01-02 홈 (`/app`)
- **[UI]** 환영 문구와 바로가기 카드 5개(생산 지시, BOM, 공정 라우팅, 작업장 관리, 생산 실적). 좌측 사이드바 + 상단 햄버거/홈 아이콘, 하단에 사용자명·내 계정정보·로그아웃. `/app/mes`는 `/app`으로 이동한다.

### 01-03 사이드바 전체 메뉴
- **[UI]** `메뉴구성표.md` 참조. 캡처: `01_시스템시작/01-03_사이드바_전체메뉴.png`(1600×2100).

## 07 POP (현장 작업자 화면) — 핵심

POP는 `/pop/*` 경로이며 관리자 웹(`/app`) 정책과 별개다. 관리자 세션으로도 열린다(이번 조사 방식). 상단 바: 로고, 현재 시각, 작업자명, [시스템모드](관리자 웹으로 이동), [로그아웃], 탭 [작업대기](`/pop/work-select`) / [생산실적](`/pop/production`) [UI+SRC].

### 07-01 작업선택 (`/pop/work-select`) — 캡처 `07-01_POP_작업선택_*`
- **[UI]** RELEASED·IN_PROGRESS 작업지시 카드 목록(납기순) [SRC getTodayWorkOrders]. 카드: 작업지시번호, 품목, 제조번호, 상태(대기/진행중), 계획수량, 공정 진행률(완료공정/전체), 공정명 흐름.
- 조회: **공정별 조회**(칩, 진행중·대기 작업이 있는 공정만, 전체 공정 + 공정명별 건수), **작업 상태**(전체/진행중/대기), **통합 검색**(작업지시번호·제조번호·품목·공정·설비), **WIP QR 스캔**(라벨 QR로 작업지시 찾기) [UI+SRC].
- 카드를 누르면 해당 작업 화면으로 **이동만** 한다(데이터 변경 없음). 공정을 선택했으면 그 공정, 전체이면 진행중/대기 중 첫 공정 [SRC work-select-client].
- 작업자 로그인(PIN) 세션이면 본인 사업장의 작업지시만 보인다 [SRC].
- S02: WO-2026-004(PIPE, 진행중, 1/8). S05: WO-2026-008(PIPE, 대기, 0/8). S03: WO-2026-006, S04: WO-2026-007도 목록에 표시 [UI].

### 07-02 작업 화면 (`/pop/production/{operationId}?assignmentId=…`) — 캡처 `07-02_POP_작업화면_*`
화면 구성 [UI+SRC production-client]: 작업지시번호·품목·상태 뱃지, 현재 공정, **설비**(설비배정 기준), 배정수량/완료수량/잔여수량(설비배정이 있을 때), 진행률 바, 자재 기준 가능수량 박스(계획수량·누적실적·자재기준 가능·추가 생산가능), 실적 이력(최근 5건).

| 상태 | 화면 | 근거 |
|---|---|---|
| 자재 미출고(원본 WIP 없음) | "자재출고가 완료되지 않아 작업을 시작할 수 없습니다. 먼저 자재출고를 처리해 주세요." — 시작 버튼 없음 | S05 WO-2026-008 1공정 [UI] |
| 대기 + 앞 공정 미완 또는 가능 | [작업 시작] 버튼 | S02 WO-2026-004 3공정 [UI]. 시작 가능 여부는 서버가 재검증 [SRC assertOperationStartAllowed] |
| 진행중 | 생산실적등록: **양품/불량/재작업** 수량(직접 입력 + −10 −1 +1 +10 +100, 초기화), [실적 등록] | S02 2공정 [UI] |
| 불량 수량 > 0 | **불량 원인 입력(자주검사)** 패널: 불량코드 선택 + 수량, [+ 불량코드 추가]. 합계가 불량수량과 일치해야 등록 | [SRC] 화면은 불량 입력 시에만 나타나 직접 열어 보지 못함 [미확인(UI)] |
| 완료 | [작업 목록으로] | S02 1공정, S04 1공정 [UI] |

동작 규칙(소스 [SRC pop.actions.ts] — 버튼은 누르지 않음):
1. **작업 시작**(`startOperation`): 작업자 로그인 필요, 설비배정이 있는 공정은 배정(`assignmentId`) 필수, **앞 공정이 모두 완료**되어야 하고 **자재출고(원본 WIP) 완료**여야 함. 시작하면 공정 PENDING→IN_PROGRESS, 작업지시 IN_PROGRESS, WIP 상태 전이.
2. **실적 등록**(`submitProductionResult`): 합계 1 이상, 소수점 6자리까지, 불량>0이면 불량코드 수량 합계 일치 필수, 설비배정 공정은 설비배정 시작 후, **전공정에서 넘어온 가능 수량(WIP)과 자재 출고분(BOM) 기준 한도 초과 불가**, 잔여수량 초과 불가.
3. 불량·재작업 수량은 WIP이 분리되어(폐기/재작업) 다음 공정 투입 가능 수량에서 빠짐(검증 S04).
4. **별도의 "작업 완료" 버튼은 없다** — 공정 완료수량이 계획에 도달하면 공정이 완료되는 구조로 보이나 정확한 완료 전이 코드는 이번에 끝까지 읽지 않음 [미확인]. 다음 공정은 앞 공정 완료 후 [작업 시작]이 가능해지는 방식 [UI: S02 3공정 대기].
5. **설비 선택 UI는 POP에 없다.** 작업지시 설비배정(`assignment`)이 정해 준 설비가 표시되고, 카드 → 작업 화면 경로가 `assignmentId`를 넘긴다 [SRC operationHref]. 설비배정이 없는 공정(예: 외주·검사)은 설비 "-".
6. **외주 공정**: S03 WO-2026-006 5공정(분체도장, 외주출고 후 외주 중)에도 POP 작업 화면에 실적등록 폼이 표시된다 [UI]. 외주 중 재공에 실적을 등록할 수 있는지는 확인하지 못함 [미확인] → 매뉴얼에서 현장 작업자 절차로 안내하지 말 것(`기능오류및주의사항.md` 참조).

### 07-04 오늘의 생산실적 (`/pop/production`)
- **[UI]** 오늘 양품/불량/재작업 합계 카드 3개와 실적 목록(작업지시·품목·공정·시각·수량). S01~S04 실적이 오늘(2026-11-11) 날짜로 표시된다(시나리오를 오늘 생성했기 때문).

### 07-05 관리자 웹 내 작업대기 (`/app/pop/work-queue`)
- **[UI]** 메뉴에는 없고 직접 URL로만 열린다. 공정별 작업 큐(전체/대기/진행중/작업가능/작업불가 필터, 공정 칩, 검색: 작업지시번호·제조번호·품목·공정·설비). 허용 경로(`/app/pop`)에는 포함됨 [SRC daewon-scope].

### 07 POP 로그인 이후 흐름(작업자모드) — [미확인]
PIN 로그인→작업선택→작업 화면 전체 흐름은 PIN 입력이 로그인 기록을 남겨 실행하지 않았다. 관리자 세션으로 같은 화면을 열어 구성만 확인했다.
