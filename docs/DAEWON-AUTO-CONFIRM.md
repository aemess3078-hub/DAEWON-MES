# 수주·생산계획 자동 확정 정책 (초안 단계 제거)

현장 사용성 개선을 위해 수주관리와 생산계획의 "초안" 단계를 없앴다. 신규 기능이 아니라 기존 업무 절차의 간소화이며 DB 스키마·Enum은 바꾸지 않았다.

## 1. 정책 요약

| 대상 | 등록 경로 | 저장 상태 |
|---|---|---|
| 수주 | 수주 등록(`createSalesOrder`) | **CONFIRMED** |
| 생산계획 | 수주 생산의뢰·수주+여유 생산의뢰(`requestProductionFromSalesOrder`) | **CONFIRMED** (ORDER / ORDER_EXTRA) |
| 생산계획 | 재고 생산계획 등록(`createPlan`) | **CONFIRMED** (STOCK) |

- 서버가 화면 값과 무관하게 정한다. 요청에 상태가 없거나 초안·확정이면 확정으로 저장하고, 그 외 상태(생산중·출하·완료·취소 등)로는 등록할 수 없다.
- 등록 화면에서 상태 선택 항목을 없애고 "등록하면 바로 확정됩니다" 안내만 보인다.
- 확정은 "작업지시를 만들 수 있는 상태"이지 생산이 시작됐다는 뜻이 아니다. 작업지시 생성 → 계획 진행중, POP 실적·전 공정 완료 → 계획 완료, 출하 → 수주 부분출하·출하완료의 기존 자동 전이는 그대로다. 작업지시는 자동 생성하지 않는다.
- 수주의 `IN_PRODUCTION`은 기존처럼 "생산의뢰 시점"에 바뀐다(의미 변경 없음).

## 2. 기존 초안 데이터

- 기존 DRAFT 수주·계획은 일괄 변경하지 않는다. 목록 조회와 수정 화면의 개별 확정(초안→확정)은 그대로 쓴다.
- 초안 계획은 확정하기 전에는 작업지시를 만들 수 없다(기존 정책).
- 기존 초안 수주에도 생산의뢰는 가능하다(기존 동작 유지, 확정을 거치지 않고 생산중이 된다).
- 여유 생산 승인 상태(`extraApprovalStatus`)는 DB 기본값을 그대로 둔다. 자동 확정을 이유로 승인 처리하지 않으며, 기존 PENDING 값도 보존한다. 승인 정책은 아직 적용되어 있지 않다.
- LOT·재고·수불 데이터는 변경하지 않는다.

## 3. 수주 수정 정책 (입력 실수 정정)

수주가 바로 확정되므로 입력 실수를 고칠 수 있어야 한다. 품목·수량·단가 수정 규칙은 서버(`updateSalesOrder`)와 화면이 같은 순수 함수(`salesOrderItemEditBlockReason`, `src/lib/sales-order-status.ts`)를 쓴다.

- 초안·확정 수주에 **후속 업무가 없으면** 품목·수량·단가를 수정할 수 있다. 후속 업무는 취소되지 않은 생산계획, 작업지시, 출하(예정 포함), 출하 수량이다.
- 후속 업무가 있거나 생산중·부분출하·출하완료·완료·취소 상태이면 품목·수량 수정은 거부한다(연결된 계획·출하 번호를 안내). 품목이 그대로인 일반 수정(비고·고객·납기 등)은 허용한다.
- 품목 줄은 지우고 다시 만들지 않고 **제자리에서 수정**한다(줄 ID 보존). 취소된 생산계획·출하 이력이 걸린 줄은 삭제할 수 없고 수량만 수정할 수 있다(이력 연결 보호).
- 입력 검증: 품목 0건, 같은 품목 중복, 수량 0 이하, 음수 단가는 거부한다.
- 같은 수주 품목의 생산의뢰·출하와 같은 행 잠금으로 직렬화한다. 수정과 생산의뢰가 동시에 와도 수주 충당 합계가 수주 수량을 넘지 않는다.
- 수정 화면은 기존 품목 납기·비고와 헤더 비고를 불러와 저장 시 지워지지 않게 한다.
- 잘못 등록한 수주를 되돌리는 경로(확정→초안 복귀: 후속 업무가 없을 때만, 취소, 초안 삭제)는 그대로 유지한다.

## 4. 권한

- 확정 전용 권한은 없다(SALES_ORDER·PRODUCTION_PLAN은 조회/등록/수정/삭제뿐). 기존 등록 화면도 등록 권한(CREATE)만으로 확정 등록을 고를 수 있었으므로 권한 범위는 넓어지지 않았다.
- 수주 등록은 MANAGER·OPERATOR, 생산의뢰는 수주 UPDATE + 생산계획 CREATE(MANAGER), 재고 계획 등록은 생산계획 CREATE(MANAGER), 초안 개별 확정과 수주·계획 수정은 각 UPDATE 권한이 필요하다. 자동 확정이 이 검증을 우회하지 않는다.

## 5. 견적 → 수주 전환 (DRAFT 생성 예외)

`convertToSalesOrder`(`src/lib/actions/quotation.actions.ts`)는 DRAFT 수주를 만든다. 이 경로는 대원정밀 구축 범위 밖이라 **변경하지 않고 예외로 문서화**한다.

- `/app/mes/quotations`는 대원정밀 허용 경로(`DAEWON_ALLOWED_ROUTES`)에 없고, 견적(QUOTATION) 권한은 일반 역할에 부여하지 않는다.
- 서버 액션은 `assertDaewonFeatureScope()`로 개발자 계정(`test`) 외에는 거부한다(E2E AC-19에서 일반 계정 거부와 개발자 경로의 DRAFT 생성을 함께 기록).
- 향후 견적 메뉴를 대원정밀에 열 때는 이 전환도 CONFIRMED로 바꾸는 것을 함께 결정해야 한다.

## 6. 알려진 별도 결함 (이번 변경과 무관, 유지)

- D-01: 일부 화면의 `[Table] Column with id 'undefined'` 콘솔 오류(7개 화면, 무해).
- N-13: 수주 등록 서버 검증 부족(품목 0건·수량 0 등). 수정 경로는 이번에 검증을 넣었지만 등록 경로는 그대로다.
- N-16: 수동 발주 서버 검증 부족.

## 7. Production 배포 시 주의

- DB 마이그레이션 없음. 롤백 대상은 배포 전 Production 커밋(`aaebf51`).
- 배포 전 운영의 DRAFT 수주·계획 건수를 확인한다. 자동으로 바뀌지 않으므로 수정 화면에서 개별 확정하거나 정리한다.
- 배포 후 로그인 상태에서 수주 등록·수주 수정·생산계획 등록 화면과 생산의뢰를 직접 확인한다.
